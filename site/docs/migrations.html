Migrations

Karbon migrations are versioned, native (run through sqlx — no external mysql/psql binary) and entity-first: your entities are the source of truth, and migrate diff generates the SQL to match them.

The entity-first workflow

Generators do not write migrations. Instead, you define entities, then ask migrate diff to compare them against the live database and write the delta — the Doctrine approach.

karbon generate crud Post title:string body:text   # entity, repo, controller — no SQL
karbon migrate diff init                            # writes migration/0001_init.sql
karbon migrate                                      # applies it

Add a field to the entity later, and diff again:

# add `rating:int` to the Post entity, then:
karbon migrate diff add_rating
# → ALTER TABLE posts ADD COLUMN rating … (with a matching DROP in -- migrate:down)
karbon migrate

Additive and safe. migrate diff only creates missing tables and columns. It never drops or alters existing schema, so an accidental field rename won't destroy data — review the generated file before applying it. When nothing changed, nothing is generated.

Commands

CommandWhat it does
karbon migrateApply all pending migrations (up)
karbon migrate statusList applied vs pending migrations
karbon migrate rollbackUndo the last applied migration (down)
karbon migrate diff [name]Generate a migration from the entity ↔ DB diff

How the diff works

migrate diff:

  1. Detects the driver from the connection URL (SQLite / PostgreSQL / MySQL).
  2. Introspects the database — information_schema for MySQL/PostgreSQL, sqlite_master + PRAGMA table_info for SQLite.
  3. Parses app/src/entity/*.rs for structs with an id field, reading the table name from #[table_name("…")] (or the pluralised struct name) and the columns from the fields.
  4. Computes the difference: a new entity → CREATE TABLE; a new field → ALTER TABLE … ADD COLUMN.
  5. Writes a numbered file migration/NNNN_<name>.sql with up and down sections, using driver-correct DDL.

Field Rust types map to driver-appropriate column types — for example String → VARCHAR(255) (or TEXT on SQLite), and id uses AUTO_INCREMENT / BIGSERIAL / AUTOINCREMENT respectively.

Migration file format

Migrations are plain .sql files with optional up/down sections (dbmate style):

-- migrate:up
CREATE TABLE posts (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(255) NOT NULL,
  body TEXT NOT NULL
);

-- migrate:down
DROP TABLE posts;

Without a -- migrate:up marker, the whole file is treated as the up migration (no rollback). Files are numbered without collision — the next number is max(NNNN) + 1.

Versioning

A tracking table _karbon_migrations records which versions have been applied, so each file runs exactly once. karbon migrate reads DATABASE_URL, or the DB_* variables from .env, and supports MySQL/MariaDB and PostgreSQL through the sqlx Any driver.

From Studio. migrate diff, migrate, status and rollback are all available from the Studio Terminal tab (rollback asks for confirmation). See Studio.
