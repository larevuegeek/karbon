Frontend & rendering

A full Karbon project pairs the Rust backend with a SvelteKit or Next.js frontend. In production a single binary serves both, proxying non-API requests to the Node SSR process. You can also render HTML server-side from Rust.

Choosing a frontend

karbon new my-app                     # SvelteKit (default)
karbon new my-app --frontend nextjs   # Next.js
karbon new my-app --skeleton micro    # no frontend at all

The choice is recorded in karbon.toml under [frontend] framework = "svelte" | "nextjs". A micro skeleton omits the section and serves an HTML welcome page from the backend.

Dev mode

karbon dev runs the frontend's own dev server (Vite for SvelteKit) alongside the backend, both with hot-reload. Saving a Rust file recompiles and restarts the backend; the frontend reloads independently.

Production: one port

karbon serve starts the Node SSR process and the Rust binary, and adds a fallback that proxies every non-API request to the frontend. This is driven by the KARBON_FRONTEND_URL environment variable, which serve sets automatically.

karbon build   # frontend build + cargo build --release
karbon serve   # single public port; reverse proxy to SSR built in

Because everything is fronted by the Rust binary, you deploy and operate one process (plus the Node SSR child). See Deployment.

Server-side rendering from Rust

When you want Rust to render HTML directly, the Renderer trait abstracts over three interchangeable engines, selected by feature flag:

FeatureEngine
templatesTemplateEngine (Tera) — filters + email rendering
minijinjaMinijinjaEngine
native-templatesNativeEngine — a dependency-free in-house engine
 
use karbon::template::{Renderer, MinijinjaEngine};

let engine = MinijinjaEngine::new("./templates")?;
let html = engine.render("page.html", &json!({ "title": "Hi" }))?;

The native engine supports {{ var }}, filters (| upper, | safe), {% if/elif/else %}, {% for %} with loop.*, template inheritance ({% extends %}/{% block %}), {% include %}, comments and auto-escaping. Application code can depend on Arc<dyn Renderer> so the backend is swappable.

Inertia & LiveWire

For SPA-like apps without a separate API, use the Inertia.js adapter; for server-driven interactivity without a JS framework, use LiveWire components. Both are covered in Realtime & background.

The welcome page

A fresh full project ships a live mini-profiler home page (version, environment, features and entities, pulled from /_studio/api/info) with links to the API, the docs and Studio — a useful starting dashboard while you build.
