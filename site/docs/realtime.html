Realtime & background work

WebSocket channels for realtime, plus a message bus, jobs and events for async work — all in-process, with the option to persist jobs to the database.

WebSocket channels

ChannelRegistry manages rooms: clients join/leave, and you broadcast from anywhere — a controller, a job, an event handler.

use karbon::channel::ChannelRegistry;

let channels = ChannelRegistry::new();

Router::new().route("/ws/channels",
    get(|ws: WebSocketUpgrade, State(ch): State<ChannelRegistry>|
        ws.on_upgrade(move |socket| ch.handle_socket(socket))));

channels.broadcast("chat/room-1", "new_message", &message).await;

The client JSON protocol:

{"channel": "chat/room-1", "event": "join",    "payload": {}}
{"channel": "chat/room-1", "event": "message", "payload": {"text": "hello"}}
{"channel": "chat/room-1", "event": "leave",   "payload": {}}

Message bus

A unified bus (Symfony Messenger style) that generalises events (fan-out) and jobs (background + retry). Handlers are fallible; two transports — sync and background — with retry/backoff and a dead-letter path.

use karbon::message::{Message, MessageBus, RetryPolicy};

struct SendWelcome { email: String }
impl Message for SendWelcome {}

let bus = MessageBus::new(4);          // 4 background workers
bus.handle::<SendWelcome, _, _>(|msg| async move {
    send_email(&msg.email).await?;     // -> anyhow::Result<()>
    Ok(())
}).await;

bus.dispatch(SendWelcome { email }).await?;       // sync: run & await result
bus.dispatch_async(SendWelcome { email }).await;  // background: worker + retry

Use MessageBus::with_retry(workers, RetryPolicy { max_retries, backoff }) to tune retries.

Background jobs

let queue = JobQueue::new(4);          // 4 workers
queue.push(SendEmailJob { to: "foo@bar.com".into() }).await;

For jobs that must survive a restart, use the persistent queue backed by a _karbon_jobs table:

let queue = PersistentQueue::builder(pool)
    .register::<SendEmailJob>()
    .build();
queue.migrate().await?;
queue.push(&job).await?;
queue.start(interval).await;           // retry + dead-letter

Events

let bus = EventBus::new();
bus.on::<UserCreated>(|event| async move { /* send email */ }).await;
bus.emit(UserCreated { user_id: 1 }).await;

LiveWire components

Server-rendered interactive components — HTML over WebSocket, no JS framework. The server renders, handles events and re-renders; the client patches the DOM.

impl LiveComponent for Counter {
    fn render(&self) -> String {
        format!("<span>{}</span><button lw-click=\"inc\">+</button>", self.count)
    }
    // handle_event(&mut self, event, params) → mutate state
}

Client directives: lw-click, lw-submit, lw-input, lw-param-*, with automatic reconnect.

Inertia.js adapter

Return pages instead of JSON: the first visit serves full HTML, subsequent navigations return JSON and the client swaps the component.

Inertia::render("Dashboard", json!({ "user": user, "stats": stats }))
Inertia::location("/dashboard")   // after POST/PUT/DELETE

Other building blocks

  • Cache — memory / file / Redis backends behind one Cache facade, with tags and a remember() cache-aside helper, plus an HTTP cache (ETag + 304) middleware.
  • Mail — SMTP via lettre, integrated with the template engine.
  • i18n — I18n::t("key") and t_with for interpolation.
  • Images — a full ImageProcessor pipeline (resize, crop, watermark, formats) with EXIF auto-orientation.
  • Scraping — a polite HTTP client with CSS parsing and robots.txt checks (feature scraping).
  • HMR — a dev file watcher that hot-swaps CSS and reloads on other changes.
