Studio — the dev cockpit

Studio is a browser dashboard embedded in your app during development: live metrics, a schema and route explorer, an integrated terminal that runs CLI commands, and your project's docs. It's feature-gated and never compiled into production.

Enabling Studio

Studio lives behind the studio feature flag:

karbon = { package = "karbon-framework", features = ["studio"] }

Projects scaffolded with --local enable it automatically. On startup you'll see:

⚡ Studio → http://localhost:3005/_studio?token=…

In development the token requirement is relaxed — the printed links work without it. Studio binds to localhost only and is disabled in production (the code isn't compiled without the feature).

Tabs

TabWhat it shows
OverviewVersion, environment, driver, uptime, and live performance (avg/min/max latency, status & method distribution, slowest endpoints), plus features and entities
Requests / Events / Jobs / MailsRealtime monitoring over a WebSocket (/_studio/ws)
DatabaseA schema browser: tables, row counts and columns
RoutesEvery route classified as System / API / Web, with params and constraints, from /openapi.json plus system routes
TerminalA whitelisted CLI runner + a scaffolding form (see below)
DocsThe embedded Karbon reference plus your project's docs/**.md, rendered to HTML

The integrated terminal

The Terminal tab runs a whitelist of karbon commands — generate/g, migrate, doctor, docs — with no shell access. Destructive actions like migrate rollback ask for confirmation first.

It includes a Make form for scaffolding, with a visual field builder: add rows of name + type + nullable, exactly like the CLI's interactive assistant, then run the generator. There's a command catalog and autocomplete.

Commands run non-interactively (stdin is closed) so the interactive field assistant never blocks the terminal. The karbon binary is located via KARBON_BIN, which karbon dev sets for you.

API endpoints

GET  /_studio/api/info       # version, env, driver, features, entities
GET  /_studio/api/data       # realtime monitoring payloads
GET  /_studio/api/stats      # performance stats
GET  /_studio/api/database   # schema (tables, rows, columns)
GET  /_studio/api/docs       # rendered docs (reference + project)
POST /_studio/api/terminal   # run a whitelisted command

Debug toolbar

On HTML pages, studio_toolbar_middleware injects a bottom toolbar showing the framework version, request method, path, status, duration and request-id, with a drop-up of details and links to Studio and the Terminal. It's wired automatically by App::serve().

Loading new assets. Studio's UI assets are embedded in the binary. After updating the framework, restart karbon dev so the backend recompiles and serves the latest cockpit, then hard-refresh the browser.
