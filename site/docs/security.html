Security & auth

Authentication is JWT-based with refresh-token rotation; authorization uses a Symfony-style role hierarchy resolved by an AuthGuard extractor. Sensible security defaults are on out of the box.

Passwords

Passwords are hashed with Argon2id (with bcrypt support for legacy hashes). Password policy requires at least 12 characters with upper, lower and a digit.

use karbon::security::Password;

let hash = Password::hash("correct horse battery staple")?;
let ok   = Password::verify("…", &hash)?;

JWT & refresh tokens

  • Access tokens: HS256, 15-minute lifetime.
  • Refresh tokens: 30-day lifetime, with rotation on each use.
  • Refresh tokens are stored SHA-256-hashed in the database — never in clear text.

The signing secret comes from JWT_SECRET. Leaving it empty disables auth entirely (useful for prototypes).

AuthGuard

AuthGuard is an Axum extractor that verifies the JWT and resolves the role hierarchy. Inject it into a handler to require — and read — an authenticated user.

#[karbon::get("/me")]
async fn me(auth: AuthGuard) -> AppResult<impl IntoResponse> {
    auth.require_role("ROLE_USER")?;
    Ok(Json(json!({ "id": auth.user_id(), "roles": auth.roles() })))
}

⚠️ A route that carries a role must take an auth: AuthGuard parameter — enforced. If a route has a role (#[require_role("…")] or a controller-level role = "…") but no auth: AuthGuard, the macro refuses to compile instead of silently leaving it unprotected. Add auth: AuthGuard.

Role hierarchy

Roles inherit downward, so checking a lower role passes for a higher one:

ROLE_SUPER_ADMIN → ROLE_ADMIN → ROLE_REDACTEUR, ROLE_MODERATEUR → ROLE_USER

auth.require_role("ROLE_ADMIN") succeeds for a ROLE_SUPER_ADMIN. Protect a whole controller with role = "…", or a single handler with #[require_role]. See Routing.

Firewall (access control)

For app-wide rules, install a Symfony-style firewall: declarative URL-pattern → roles, enforced centrally before your handlers. Rules are checked top-to-bottom, first match wins.

use karbon::security::AccessControl;

App::new().router(base)
    .firewall(AccessControl::new()
        .public("^/login")
        .public("^/health")
        .rule("^/admin", ["ROLE_ADMIN"])          // /admin* → ROLE_ADMIN
        .rule("^/api/account", ["ROLE_USER"])      // → ROLE_USER (or higher)
        .default_deny(false))                      // unmatched → allowed (default)
    .serve().await?;

Decisions: unmatched + default_deny(false) → allow · unmatched + default_deny(true) → 403 · public → allow · matched but unauthenticated → 401 · matched but missing role → 403. The firewall composes with per-controller and per-route guards (defense in depth), and respects the role hierarchy.

Rate limiting is opt-in by design — behind a reverse proxy or NAT, a naive per-IP limit can punish many users sharing one address. Enable it once you know your topology.

Input & transport hardening

  • Route validation — declarative rules reject bad path params with 400 before the handler. See Validation.
  • Uploads — magic-byte type checks, SVG sanitization, path-traversal protection, decompression-bomb limits on images.
  • SQL — SelectBuilder binds all values and validates identifiers; the derive macros bind too.
  • HTML — util::Html::sanitize / strip_tags (ammonia) for user content; Inertia and LiveWire escape embedded props.
  • CORS — configurable, with a restrictive fallback when unset.
  • Cookies — httpOnly + SameSite=Lax, and Secure over HTTPS.
  • Production errors — internal error details are hidden from clients.

Diagnostics. karbon doctor flags missing or weak security config offline; doctor --db also checks the database. See the CLI reference.
