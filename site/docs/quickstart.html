Quickstart

Scaffold a full-stack app, add an entity, generate its admin, run the migration and start the dev server — in about five minutes.

1. Create a project

karbon new my-app          # SvelteKit frontend (default)
cd my-app

Other starting points:

karbon new my-app --frontend nextjs   # Next.js instead of SvelteKit
karbon new my-app --skeleton micro    # backend-only, no frontend
karbon new my-app --template blog     # Post CRUD + admin pre-scaffolded

A full project contains a Rust backend (app/), a frontend, a karbon.toml config and a starter docs/ folder. See Project structure for the full layout.

2. Configure the environment

Copy the example env file and set your database (or leave it blank to run without one):

cp .env.example .env

For a quick start with zero setup, SQLite needs nothing but a path. For MySQL/PostgreSQL, set DB_* or a single DATABASE_URL. Karbon loads .env files in cascade (.env → .env.{env} → .env.local), Symfony-style. See Configuration.

No database? Leave DB_NAME empty and the app starts without connecting. Perfect for prototypes and static pages.

3. Generate an entity + CRUD

Scaffold an entity, repository and controller from typed fields in one command:

karbon generate crud Post title:string body:text published:bool

Field syntax is name:type, with a trailing ? for nullable columns. Available types: string, text, int, bigint, float, bool, datetime, date, json. Run generate entity Post -i for an interactive, Symfony-style field assistant. See Generators.

4. Generate the admin UI

karbon generate admin Post

This produces a field-aware back-office (list, create/edit forms, delete) under /admin/posts, guarded by ROLE_ADMIN, with typed DTOs derived from your entity's fields.

5. Create and run the migration

Generators don't write migrations — your entities are the source of truth. Diff them against the database to produce the migration, then apply it:

karbon migrate diff init   # writes migration/0001_init.sql from the entity ↔ DB diff
karbon migrate             # applies pending migrations

Later, when you add a field to an entity, run karbon migrate diff add_field to generate the ALTER TABLE. The diff is additive and never drops or alters existing columns. See Migrations.

6. Start developing

karbon dev

This compiles and runs the backend, starts the frontend dev server, and watches both for changes — saving a Rust file recompiles and restarts the backend automatically. Your app is now live with hot-reload.

Open the cockpit. In dev, Studio is available at http://localhost:3005/_studio — live metrics, a schema and route explorer, and an integrated terminal that can run generators and migrations for you. See Studio.

7. Build & deploy

karbon build                 # production build (frontend + cargo --release)
karbon serve                 # run production on a single port (reverse proxy built in)
karbon deploy docker         # generate a multi-stage Dockerfile
karbon deploy publish:build  # build & rsync to a VPS (PM2 / systemd)

See Deployment for VPS, Docker and PaaS targets.
