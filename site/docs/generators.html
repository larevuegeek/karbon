Generators & scaffolding

The karbon generate family scaffolds entities, repositories, controllers and a field-aware admin — and wires the routes into main.rs for you. Generators never write migrations; you diff entities instead.

Field syntax

Fields are name:type, with a trailing ? for a nullable column:

title:string  body:text  views:int  price:float  published:bool
published_at:datetime  meta:json  summary:text?
TypeRustTypical column
stringStringVARCHAR(255)
textStringTEXT
inti32INT
biginti64BIGINT
floatf64DOUBLE / REAL
boolboolBOOLEAN
datetimeDateTime<Utc>DATETIME / TIMESTAMP
dateNaiveDateDATE
jsonserde_json::ValueJSON

A trailing ? makes the field Option<T> and the column nullable.

generate entity

karbon generate entity Post title:string body:text published:bool

Creates the entity struct in app/src/entity/. It does not create a migration — run karbon migrate diff afterwards.

Interactive assistant

Omit the fields (or pass -i/--interactive) to launch a Symfony-style field assistant that prompts for each field by name, type and nullability:

karbon generate entity Post -i

The assistant activates automatically when no fields are given and you're on a TTY. It's also exposed in the Studio Terminal as a visual field builder (rows of name + type + nullable).

generate controller

karbon generate controller Post

Generates a controller stub with validated {id} routes (id = "int:min=1") and mounts it in main.rs.

generate crud

karbon generate crud Post title:string body:text

The all-in-one: entity + repository + controller, wired into routes and OpenAPI. Run migrate diff next to create the schema.

What generate crud gives you

A working REST API under the API prefix, behind ROLE_ADMIN (the generated file says how to open reads):

GET    /api/v1/posts?page=1&per_page=20&sort=id&order=desc&search=…
GET    /api/v1/posts/{id}        404 when missing
POST   /api/v1/posts             201 with the new row
PUT    /api/v1/posts/{id}        partial: only the fields sent change
DELETE /api/v1/posts/{id}        204

A text field is written pub body: String, // karbon:text in the entity: the marker makes migrate diff create a TEXT column (a plain String is a VARCHAR(255) under MySQL and PostgreSQL) and the admin render a textarea. // karbon:unique asks for a UNIQUE column the same way.

generate admin

karbon generate admin Post

Produces a field-aware PostAdminController (prefix /admin/posts, ROLE_ADMIN). It reads the entity's fields and generates the list view, create/edit forms, and typed New/Update DTOs with per-type coercion (string/number/bool/date/json, nullable handled). CSRF is wired via a small X-CSRF-Token script, and {id} routes are validated. Run it after generate crud.

generate auth

karbon generate auth

The accounts of your application, ready to use: sign-up, sign-in, sign-out, session renewal and password reset. It writes four files you own and can edit — entity/user.rs, entity/auth_token.rs, service/auth.rs (the logic) and controller/auth_controller.rs:

  • browser pages with session cookies, under /auth: login, register, forgot, reset, account, logout;
  • their JSON twins under the API prefix: POST /auth/login, register, refresh, logout, forgot, reset, and GET /auth/me.

Sessions renew themselves. The access token is short-lived (JWT_EXPIRATION, 15 minutes by default); a refresh token (REFRESH_TOKEN_EXPIRATION, 30 days) buys the next one. It works once, only its keyed hash is stored, and deleting it ends the session.

Password reset emails a one-hour, single-use link (set SMTP_HOST; without it, in development, the link is written to the log). Using it signs the account out everywhere.

Then create the table and your first administrator:

karbon migrate diff && karbon migrate
karbon user create you@example.com --admin

Signing up through the application always gives ROLE_USER; karbon user promote <email> makes an existing account an administrator. generate auth also sets LOGIN_PATH=/auth/login in .env, so a browser that opens a protected page without a session is sent to the login page. It takes no name, and karbon new --template blog runs it for you.

karbon g is the short alias for karbon generate.

Route wiring

Generators insert routes and OpenAPI paths at the marker comments in main.rs (// karbon:routes, // karbon:api-routes, // karbon:openapi-*), nesting each controller under its prefix. You don't edit the wiring by hand. See Routing & controllers.

Typical flow: generate crud → generate admin → migrate diff → migrate → dev.
