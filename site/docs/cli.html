CLI reference

The karbon binary covers the whole lifecycle of a project. Every command is listed here with its key flags.

new

Scaffold a new project.

karbon new my-app                     # SvelteKit (default)
karbon new my-app --frontend nextjs   # Next.js frontend
karbon new my-app --skeleton micro    # backend-only (no frontend)
karbon new my-app --template blog     # Post CRUD + admin starter
karbon new my-app --local ./karbon    # depend on a local framework checkout
FlagValuesDefault
--frontendsvelte / nextjssvelte
--skeletonfull / microfull
--templateblog—
--localpath to karbon repocrates.io

dev

Run the backend and frontend together with hot-reload. A native file watcher recompiles and restarts the backend when you save a Rust file; the frontend runs its own dev server (Vite). Studio is available in dev.

karbon dev

build / serve

karbon build    # npm build + cargo build --release
karbon serve    # run production on a single port (reverse proxy to Node SSR built in)

serve starts the Node SSR process and the Rust binary, and proxies non-API requests to the frontend. Set KARBON_FRONTEND_URL to point the proxy elsewhere (done automatically by serve).

generate (alias: g)

Code generators. Routes and OpenAPI paths are wired into main.rs automatically.

karbon generate entity Post title:string body:text published:bool
karbon generate entity Post -i        # interactive field assistant
karbon generate controller Post       # controller stub (validated routes)
karbon generate crud Post title:string body:text   # entity + repo + controller
karbon generate admin Post            # field-aware back-office (run after crud)
karbon g crud Post --dry-run          # preview without writing
karbon g crud Post --force            # overwrite existing files

Field syntax: name:type with a trailing ? for nullable. Types: string, text, int, bigint, float, bool, datetime, date, json. See Generators.

migrate

Versioned, native migrations (run through sqlx — no mysql/psql binary needed).

karbon migrate              # apply pending migrations
karbon migrate status       # list applied / pending
karbon migrate rollback     # undo the last applied migration (down)
karbon migrate diff [name]  # generate a migration from the entity ↔ DB diff

migrate diff is the entity-first workflow: it introspects the database, parses app/src/entity/*.rs, and writes a migration for the differences. See Migrations.

doctor

karbon doctor        # offline diagnostics (toolchain, layout, config)
karbon doctor --db   # also probe the DB connection & pending migrations

Exits non-zero on a blocking problem — safe for CI.

docs

karbon docs build    # render docs/**.md → static site in docs/_site/

The same Markdown sources feed the Docs tab in Studio.

deploy

karbon deploy docker          # multi-stage Dockerfile + .dockerignore
karbon deploy paas            # fly.toml, render.yaml, Procfile
karbon deploy fly             # deploy via flyctl
karbon deploy railway         # deploy via railway up
karbon deploy publish         # rsync artifacts (local or SSH)
karbon deploy publish:build   # build then publish
karbon deploy ssh             # legacy alias of publish:build

Targets are configured in the [deploy] section of karbon.toml. See Deployment.

Tip. Most generators and migration commands are also available from the Studio Terminal tab — a whitelisted, no-shell runner with a scaffolding form. See Studio.
