Configuration & environments

Configuration comes from environment variables, loaded from .env files in cascade, and from karbon.toml for project-level settings. The active environment is selected by APP_ENV.

Environment files

App::new() calls config::load_env() automatically, loading files in Symfony-style cascade — later files override earlier ones, but never an already-set variable:

.env  →  .env.{APP_ENV}  →  .env.local  →  .env.{APP_ENV}.local

So you commit shared defaults in .env, environment-specific values in .env.{env}, and machine/secret overrides in the *.local files (which you git-ignore).

APP_ENV

config::Environment plus the helpers on Config let you branch on the environment:

config.is_development()
config.is_test()
config.is_production()

Studio links are relaxed in development; internal error details are hidden in production.

Common variables

VariablePurpose
APP_ENVdevelopment / test / production
DATABASE_URLFull connection URL (alternative to the DB_* set)
DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORDDatabase connection parts. Empty DB_NAME → no DB
JWT_SECRETJWT signing secret. Empty → auth disabled
KARBON_FRONTEND_URLReverse-proxy target for non-API requests (set by serve)
KARBON_BINPath to the karbon binary (set by dev, used by Studio)
SMTP / mail varsMailer configuration (host, port, credentials)

Optional everything. DB_USER and JWT_SECRET are no longer mandatory. Leave DB_NAME empty to run without a database; leave JWT_SECRET empty to run without auth. Config::has_database() reports the mode.

karbon.toml

Project-level settings the CLI reads:

[app]
name = "my-app"

[backend]
extra_packages = []        # extra binaries to build & deploy alongside the main one

[frontend]
framework = "svelte"       # or "nextjs"; omit for a micro skeleton

[deploy]
path = "/var/www/my-app"
user = "www-data"
manager = "pm2"            # "pm2" or "systemd"
host = "user@server"       # omit for a local deploy

On the CLI side, KarbonConfig.frontend is an Option, so the absence of a [frontend] section is what makes a project backend-only.

AppState

Your handlers receive shared state through State<AppState>:

pub struct AppState {
    pub db: Database,
    pub config: Config,
    pub mailer: Option<Mailer>,
    pub role_hierarchy: RoleHierarchy,
}

Validate config offline. karbon doctor checks for missing or inconsistent configuration before you deploy; doctor --db additionally probes the connection and pending migrations.
