Database & ORM

Karbon supports MySQL, PostgreSQL and SQLite behind feature flags, with a repository trait, a typed and injection-safe query builder, derive macros for inserts/updates, and helpers for relations.

Choosing a driver

MySQL is the default. Switch drivers with feature flags on the karbon dependency:

# MySQL (default)
karbon = { package = "karbon-framework", version = "0.2" }

# PostgreSQL
karbon = { package = "karbon-framework", version = "0.2",
           default-features = false, features = ["postgres"] }

# SQLite (demos, embedded, small sites)
karbon = { package = "karbon-framework", version = "0.2",
           default-features = false, features = ["sqlite"] }

The query builders and macros use driver-abstract helpers (placeholder(n), insert_sql(), last_insert_id()), so there's no hardcoded SQL dialect in your code. For PostgreSQL, INSERT uses RETURNING id, so id columns must be bigserial.

Optional database. If DB_NAME is empty the app starts without connecting — the pool is lazy and never used. Config::has_database() reports the mode. JWT_SECRET empty disables auth.

Entities & CrudRepository

An entity is a struct with an id. Implementing CrudRepository gives it a full set of query methods:

impl CrudRepository for Post {
    const TABLE: &'static str = "posts";
    const ENTITY_NAME: &'static str = "Article";
    const HAS_SLUG: bool = true;
    const SOFT_DELETE: bool = true;   // soft delete via deleted_at
}

You get find_by_id, find_by_slug, find_all, count, delete, exists, find_where, find_all_where. With SOFT_DELETE, delete() sets deleted_at = NOW() and you gain restore(), force_delete() and find_all_with_trashed().

SelectBuilder

A typed query builder. Every value is bound — there is no string interpolation of user data, and identifiers (table, column, join, order_by) are validated to reject injection.

use karbon::db::{SelectBuilder, Order};

let users: Vec<User> = SelectBuilder::table("users")
    .columns("id, name, email")
    .where_eq("active", true)
    .where_like("name", "%alice%")
    .where_gt("age", 18)
    .where_in("role", &["admin", "editor"])
    .where_null("deleted_at")
    .order_by("created_at", Order::Desc)
    .limit(20)
    .fetch_all(&pool)
    .await?;

Supported clauses: where_eq, where_ne, where_gt/gte/lt/lte, where_like, where_null/not_null, where_in, where_raw, join, group_by, order_by, limit, offset. Execute with fetch_all(), fetch_one() or count().

Insertable & Updatable

Derive inserts and updates from a struct. #[timestamps] fills created_at/updated_at; #[slug_from(...)] generates a slug when empty.

#[derive(karbon::Insertable)]
#[table_name("posts")]
#[timestamps]
pub struct NewPost {
    pub title: String,
    #[slug_from("title")]
    pub slug: String,
    pub body: String,
}

#[derive(karbon::Updatable)]
#[table_name("posts")]
#[timestamps]
pub struct UpdatePost {
    #[primary_key] pub id: i64,
    pub title: Option<String>,
}

let id = NewPost { /* … */ }.insert(state.db.pool()).await?;

Transactions

let mut tx = state.db.begin().await?;
NewPost { /* … */ }.insert(&mut *tx).await?;
tx.commit().await?;

Relations

On CrudRepository: has_many (1-N), belongs-to via find_by_id, and load_grouped_by for batch loading that avoids the N+1 problem.

let comments = Comment::has_many(pool, "post_id", post.id).await?;       // 1-N
let parent   = Post::find_by_id(pool, comment.post_id).await?;           // belongs-to
let by_post  = Comment::load_grouped_by(pool, "post_id", &ids, |c| c.post_id).await?;
