Routing & controllers

Controllers are impl blocks annotated with macros. The macro generates the router, the route prefix and the OpenAPI paths, and injects role checks and route validation into your handlers.

Defining a controller

use karbon::prelude::*;

pub struct PostController;

#[karbon::controller(prefix = "/admin/posts", role = "ROLE_ADMIN")]
impl PostController {
    #[karbon::get("/")]
    async fn list(auth: AuthGuard, State(state): State<AppState>)
        -> AppResult<impl IntoResponse> {
        let posts = Post::find_all(state.db.pool()).await?;
        Ok(Json(posts))
    }

    #[karbon::post("/")]
    async fn create(State(state): State<AppState>, Json(input): Json<NewPost>)
        -> AppResult<impl IntoResponse> {
        let id = input.insert(state.db.pool()).await?;
        Ok((StatusCode::CREATED, Json(json!({ "id": id }))))
    }
}

The #[karbon::controller] macro generates three associated items:

  • PostController::router() — an Axum Router<AppState> with every annotated handler mounted.
  • PostController::prefix() — the route prefix string.
  • PostController::openapi_paths() — Vec<(method, full_path)> for OpenAPI aggregation.

HTTP method attributes

One attribute per route: #[karbon::get], post, put, delete, patch. The path is relative to the controller prefix.

#[karbon::get("/{id}")]
#[karbon::put("/{id}")]
#[karbon::delete("/{id}")]

Mounting routes

Routes are mounted in main.rs with .nest(prefix, router) — never .merge(). You usually don't write this by hand: the generators insert the wiring at marker comments.

let app = Router::new()
    // karbon:routes
    .nest(PostController::prefix(), PostController::router())
    .with_state(state);

The markers // karbon:routes, // karbon:api-routes, // karbon:openapi-api and // karbon:openapi-root tell karbon generate where to insert new routes and OpenAPI paths. Keep them in main.rs.

Role protection

Set a controller-wide role with role = "…", or guard a single handler with #[require_role] (per-route overrides the controller default). The check is injected at the top of the handler, before your code runs, and respects the role hierarchy (a ROLE_SUPER_ADMIN passes a ROLE_ADMIN check).

#[karbon::controller(prefix = "/admin", role = "ROLE_ADMIN")]
impl AdminController {
    #[karbon::get("/")]
    async fn dashboard(auth: AuthGuard) -> AppResult<impl IntoResponse> { /* ROLE_ADMIN */ }

    #[karbon::get("/super")]
    #[require_role("ROLE_SUPER_ADMIN")]              // overrides the controller default
    async fn super_only(auth: AuthGuard) -> AppResult<impl IntoResponse> { /* … */ }
}

⚠️ A role requires an auth: AuthGuard parameter — and it's enforced. The macro injects auth.require_role("…")? using the handler's AuthGuard. If a route carries a role (#[require_role] or a controller-level role) but has no auth: AuthGuard parameter, the macro refuses to compile — rather than silently leaving the route unprotected. Add auth: AuthGuard.

For a public route inside a role area, don't set a controller-level role; put #[require_role("…")] only on the protected routes and leave the public ones without a role.

Inject an AuthGuard extractor to read the authenticated user and check roles imperatively. For app-wide URL rules, see the firewall (access control).

Validating path parameters

Declare validation rules on the route. The macro injects a check that runs after the role check and before your handler, returning 400 if the value is invalid. The binding name must match the path parameter name.

#[karbon::get("/{id}", id = "int:min=1")]              // integer ≥ 1
#[karbon::get("/{slug}", slug = "slug")]               // ^[a-z0-9-]+$
#[karbon::get("/{status}", status = "enum:draft|published")]
#[karbon::get("/{code}", code = "regex:^[A-Z]{2}[0-9]{2}$")]

The grammar covers int, string, slug, uuid, enum: and regex:, with optional bounds. The full reference is on the Validation page.

Responses & errors

Handlers return AppResult<impl IntoResponse>. The ? operator turns an AppError into the right HTTP status (validation → 400, unauthorized → 401/403, not found → 404, …). In production, internal error details are hidden from the client.

async fn show(State(s): State<AppState>, Path(id): Path<i64>)
    -> AppResult<impl IntoResponse> {
    let post = Post::find_by_id(s.db.pool(), id).await?
        .ok_or_else(|| AppError::not_found("Article introuvable"))?;
    Ok(Json(post))
}

Convention: user-facing error messages are written in French; internal logs in English.

OpenAPI & Swagger UI

Because the macro emits openapi_paths(), the framework can build an OpenAPI 3.0 document from your controllers — including path parameters, tags derived from the path, and summaries. Skeletons serve /openapi.json and a Swagger UI at /docs.

let spec = karbon::openapi::spec("My API", "1.0.0", &routes);
// served at /openapi.json; Swagger UI at /docs

Modules & bundles

For larger apps, group routes into a Module (contributes routes) or a Bundle (routes plus a boot(&AppState) startup hook — a compile-time plugin).

impl karbon::http::Module for BlogModule {
    fn name(&self) -> &str { "blog" }
    fn prefix(&self) -> Option<&'static str> { Some("/blog") }
    fn routes(&self) -> Router<AppState> { /* … */ }
}

App::new().router(base).module(BlogModule).serve().await?;
