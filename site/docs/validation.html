Validation

Karbon validates input at two layers: declarative rules on route parameters (rejected before your handler runs), and a composable validator for request bodies that aggregates every violation.

Route parameter validation

Declare a rule next to the path in the method attribute. The macro injects the check after the role check and before your handler body, returning 400 if the value is invalid. The binding name must equal the path parameter name.

#[karbon::get("/{id}", id = "int:min=1")]
#[karbon::get("/{slug}", slug = "slug")]
#[karbon::get("/{status}", status = "enum:draft|published")]
#[karbon::get("/{code}", code = "regex:^[A-Z]{2}[0-9]{2}$")]

The parameter's type is already enforced by the Axum extractor (Path<i64> → 400 on a non-integer). These rules add value constraints on top.

Rule grammar

RuleMeaning
int, int:min=N, int:max=NInteger, optionally bounded (combine: int:min=1:max=100)
string, string:minlen=N, string:maxlen=NString length bounds
slug^[a-z0-9-]+$
uuidA canonical UUID
enum:a|b|cOne of the listed values
regex:^…$Matches the pattern (compiled regexes are cached)

You can also call the validator directly: karbon::validation::route::validate("id", &id, "int:min=1")?.

The composable validator

For request bodies, Validator collects all violations per field instead of failing on the first one — ideal for forms.

use karbon::validation::{Validator, constraints::string::{Length, NotBlank}};

let mut v = Validator::new();
v.field("name", &input.name, &[&NotBlank::new(), &Length::new().min(2).max(50)]);
v.check("age", input.age >= 18, "Vous devez être majeur");
v.nested("address", address_errors);    // nested → "address.city"
v.into_result()?;                        // AppError::Validation listing everything, or Ok

Validation groups let you reuse a struct across create/update scenarios:

let mut v = Validator::for_groups(["create"]);
v.field_in("create", "email", &input.email, &[&NotBlank::new()]);

Derive & async validators

The validator derive (validate_request) covers attribute-based field rules, while AsyncValidator handles checks that need the database — uniqueness, for example:

// reject if the email already exists
async fn validate(&self, pool: &DbPool) -> AppResult<()> {
    if User::exists(pool, "email", &self.email).await? {
        return Err(AppError::validation("email", "Email déjà utilisé"));
    }
    Ok(())
}

Forms

The form builder (Symfony-style) binds, validates and renders HTML with CSRF and auto-escaping in one place:

use karbon::form::{Form, Field};
use karbon::validation::constraints::string::Length;

let mut form = Form::new()
    .add(Field::text("title", "Titre").required().constraint(Length::new().min(3)))
    .add(Field::textarea("body", "Contenu").required())
    .csrf(token);

if form.handle(&submitted) {
    let title = form.value("title").unwrap_or_default();
} else {
    let html = form.render();   // re-render with errors
}

Validation errors become AppError::Validation, which the framework turns into a 400 with a structured body. User-facing messages are written in French by convention.
